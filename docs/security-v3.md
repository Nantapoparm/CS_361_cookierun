## Trade-off

**ทำไมใช้ SSE-KMS เฉพาะ cookierun-uploads แต่ bucket หน้าเว็บคง SSE-S3**
- Bucket cookierun-uploads นี้เก็บข้อมูลส่วนบุคคลและหลักฐาน จึงคุ้มกับความซับซ้อนที่เพิ่มขึ้น เพื่อเพิ่มความปลอดภัย
- Bucket หน้าเว็บ เป็นไฟล์สาธารณะ ไม่มีข้อมูลส่วนบุคคล การแก้ไขจำเป็นต้องไปแก้ cloudfront ด้วยก่อนให้เกิดความซับซ้อนมากขึ้นเมื่อเทียบกับความปลอดภัยที่ต้องการน้อยกว่า cookierun-uploads และหากผิดพลาดหน้าเว็บจะเปิดไม่ได้


**ข้อดี SSE-KMS**
| ข้อดี | คำอธิบาย |
|---|---|
| สิทธิ์สองชั้น | ต้องมีทั้งสิทธิ์ S3 และสิทธิ์ใช้กุญแจ จึงจะเปิดไฟล์ได้ คนที่เข้า Bucket ได้แต่ไม่มีสิทธิ์ KMS จะได้ Access Denied |
| ตรวจสอบย้อนหลังได้ | ทุกการถอดรหัสถูกบันทึกใน CloudTrail ตรวจย้อนหลังได้ว่าใครเปิดไฟล์เมื่อไหร่ |
| ตรงตามข้อกำหนด | เหมาะกับข้อมูลส่วนบุคคล การเงิน และหลักฐาน ที่ต้องพิสูจน์การควบคุมการเข้าถึง |

**ข้อเสีย SSE-KMS**
| ข้อเสีย | คำอธิบาย |
|---|---|
| ค่าใช้จ่ายเพิ่ม | Key มีราคา และมีค่า Request ตามจำนวนครั้งที่เรียก KMS |
| Latency เพิ่มเล็กน้อย | ต้องเรียก KMS |
| สิทธิ์ซับซ้อนขึ้น | ต้องดู Policy หลายตัว |
